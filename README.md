# Prompt Polish · 提示词润色

把写给 AI 的**粗糙草稿**改写成清晰、具体、可执行的提示词。三种入口，一个 ZCode 原生插件：

- **右侧面板**：输入框贴草稿 → 点动作 → 看改写结果 → 复制或发到会话
- **`/polish` 命令**：在输入框里直接敲，用当前会话模型改写
- **`prompt-polish` 技能**：说"帮我把这段话改清楚"自动触发

不用另起进程、不用改 ZCode、不用调试端口；升级 ZCode 不受影响。

## 面板长什么样

```
┌ 提示词润色                            ● ⚙ ┐
│ [把草稿贴进来，选一个动作            ]    │
│ (增强)(精简)(结构化)(中英互译)(纠错)      │
│ ┌────────────────────────────────────┐  │
│ │ 改写后的提示词…                     │  │
│ └────────────────────────────────────┘  │
│ [发送到会话] [复制]        12ms · 宿主模型 │
│ 最近改写记录…                             │
└──────────────────────────────────────────┘
```

**关于"填入输入框"**：ZCode 的插件沙箱拿不到 composer 的 DOM，宿主也没有提供写入输入框的接口（`insertComposer`、`setComposerText` 之类在程序里不存在）。所以「发送到会话」走的是 MCP Apps 的 `ui/message`——把结果作为**一条用户消息**投进当前会话，发出后可以继续让助手改，或直接让它执行。想逐字编辑再发，用「复制」。

## 安装

插件市场里添加市场再安装：

```
插件市场 → 添加 → 添加插件市场 → 填 zxc1213/zcode-polish
个人 → zcode-polish → 安装
```

或者用 CLI：

```bash
zcode plugins marketplace add zxc1213/zcode-polish
zcode plugins install zcode-polish@zcode-polish
```

装完**新会话**生效。验证：

```bash
zcode commands list | grep polish     # /polish
zcode skills list   | grep prompt-polish
```

面板入口在右侧「应用插件」里，名字是**提示词润色**。

## 面板怎么用

1. 右侧打开「提示词润色」
2. 把草稿贴在输入框，点一个动作（也可以 `Ctrl/Cmd+Enter` 用当前动作）
3. 结果出现在下面，旁边显示耗时和这次用的模型来源（宿主模型 / 面板配置）
4. `发送到会话` 直接投进会话；`复制` 留着自己改

第一次用如果显示「未配置模型接口」，有两个选择：

- **让宿主模型干活**：ZCode 如果开放了 MCP sampling，面板会自动走宿主模型，不需要任何配置
- **自己配接口**：点 ⚙ 填 Base URL / 模型 / 协议 / API Key（只存本机插件数据目录，不回传面板）

## 五个动作

| 动作 | 做什么 | 什么时候用 |
| --- | --- | --- |
| 增强（默认） | 补全目标、范围、约束与期望产出，把"帮我看看"落到具体动作 | 想法有了但说不清 |
| 精简 | 去重复、去寒暄、去空话，保留全部硬约束，约原文六成 | 草稿太长，重点被淹没 |
| 结构化 | 目标 / 现状 / 约束 / 交付物 / 验收 / 待确认 | 要交给别人执行，或需求容易扯皮 |
| 中英互译 | 转成地道英文提示词，代码与报错原文不译 | 要发给英文模型 |
| 纠错 | 只改错别字、标点、语病，最小改动 | 内容没问题，只是写错了字 |

## 命令与技能

```bash
/polish <草稿>           # 增强
/polish 精简 <草稿>
/polish 结构化 <草稿>
/polish 英文 <草稿>
/polish 纠错 <草稿>
/polish                  # 取你上一条消息作为草稿
```

命令和技能由当前会话的模型执行，**不需要配任何 Key**，还能读到项目上下文；面板则是独立调用的快速通道。

命令输出固定三段：改写结果（`text` 代码块）→ 一句改动说明 → `按改写版执行 / 再改一版 / 保持原样`，不会自动执行。

## 配置

面板设置写在插件数据目录的 `config.json`（`ZCODE_PLUGIN_DATA`）：

| 字段 | 说明 |
| --- | --- |
| `baseUrl` | **只允许公网 http(s)**；本机、内网、链路本地、保留地址一律拒绝（服务端会校验 host） |
| `model` | 模型 ID |
| `protocol` | `anthropic`、`chat`、`responses` 三选一 |
| `apiKey` | 只存本机，不回传面板；面板里可见的只有「已保存」状态 |

## 结构

```
.zcode-plugin/plugin.json   清单：skills + commands + mcpServers + ui.surfaces
commands/polish.md          /polish 命令
skills/prompt-polish/       自动触发的技能
mcp/server.mjs              MCP stdio 服务：面板资源 + 四个工具
mcp/lib.mjs                 模型调用、地址校验、配置存储、五个动作的模板
ui/panel.html               自包含面板（CSS/JS 内联，沙箱不解析子资源）
test/                       契约测试 + 面板测试
```

都不需要启动真实的 ZCode。

## 边界

- 只改写提示词，不替你完成任务、不读你的文件
- 代码块、命令、路径、标识符、URL、报错原文逐字保留
- 不虚构文件名、接口、字段、业务规则；不确定的写「待确认」
- 面板服务只访问你配置的公网接口，不发遥测、不写日志到磁盘以外的位置
